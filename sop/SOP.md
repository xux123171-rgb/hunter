# 挖洞作战 SOP v1（全谱系 · 严重→低危 · 零落地）

> 原则：不靠"经验型"预设打法。每个目标从头走完 6 个阶段，出洞按实锤判定，判死按证据判定。
> 硬约束：① 零落地——只看响应头/状态码/字节数/前几百字节，不下全量 JS/大文件；② 实锤——数据真泄露/真越权/真 RCE/真读文件才算洞，500 报错/返回 success/WAF 拦截页不算；③ 每个目标归档 D:\research\journal\<目标>\，脚本 D:\research\scratch\<目标>\，打完即删 scratch。
> 合规硬限（见 references/impact-priority-gates.md）：手动 ≤2 req/s，fuzz/扫描需放行；证明影响用"读"不外泄、PII 只留首行打码；不落点不横移；zero-destroy。
> 阶段门（进下一阶段的前置条件，不过就停+写 journal）：0→1 有 scope 逐字+红线；1→2 有 ≥1 活资产；2→3 有 ≥1 活且有面资产；3→4 有 ≥1 可枚举/无鉴权端点；4→5 finding 有 raw 证据；5→6 7问+FP-elimination 全过。
> 影响按最远可达点定级（primitive→impact 链），入口只决定"能不能进"，不决定"值多少"。

## 阶段 0 — 范围与红线（动手前 10 分钟）
- 平台/项目名、厂商、授权范围（逐字抄原文，备案号/公司全称不许脑补，用户点名要原文核对）
- 奖励类型（现金 vs 积分）、定级标准（CVSS v3.1 / v4 / 平台自定）
- 红线：禁扫描器/社工/内网渗透/DDoS 的，逐条记下；注入只证可读、越权读 ≤N 组等限额记满
- 产出：journal\<目标>\scope.md（含 ICP/备案归属链逐字记录）
- 判死前置信号（不是判死，只是预警）：注册带"提交审核"→ IDOR 线标黄；无登录态入口 → 认证型洞线标黄

## 阶段 1 — 资产测绘（纯被动，零流量）
1. 子域枚举：阿里 DoH 批量（200 常用前缀）+ crt.sh CT log + 搜索 `site:域 或 泛解析线索`
2. 官网首页源码扫：内网 IP:端口、第三方 SaaS 域、JS 引用、备案原文
3. 每个存量子域 DoH 解析（A/CNAME）→ 得到 IP 清单
- 产出：asset table（子域/IP/指纹占位），进 journal
- **关键判定点**：有"内网 IP:端口 且该 IP 公网可达"的行 → 直进阶段 2 的深打通道（hb2h 型）

## 阶段 2 — 活体普查（每个活 IP/子域，只看头）
对每个活资产，各 1 次请求拿：status、server 头、X-Powered-By、Set-Cookie（框架指纹）、404 指纹（自有页 vs 通用页）、WAF 指纹（510/特征拦截页/自研规则号）
- 指纹→洞型映射（先认识它，再打它）：
  - IIS+WebForms+Oracle → 未鉴权 ashx 接口面、sqlId 白名单枚举
  - Tomcat/Apache-Coyote 老版本 → manager 弱口令、Jasper JSP、/host-manager
  - Exchange → 三连判死法（DesiredUser→401、裸 GET→401 空、OWA SSRF 试 169.254）
  - 泛微 e-cology → /weaver/* 全 500 无堆栈 + /api/ec/v1 全 404 = 判死
  - nginx 裸 welcome 页 = 死
  - 自研 WAF（510+"触发WAF防护:xxxx"）→ 所有洞型先标"有墙"，绕过面有限
- 产出：每个资产一行指纹 + 判定（活/死/备查）
- 判死规则（证据制）：未鉴权面全 404/403 且无已知弱口令入口且无审核型注册 → 该资产认证型线判死，写证据进 journal，不再磕

## 阶段 3 — 面绘制（针对存活且有面的资产）
1. 站内链接爬（首页 + 栏目页 1 层）：form action、data-action、`$.post/ajax url` 端点全量收集
2. JS 只下**小的**（<200KB）：提取 API host、AK/SK（前端公共 key 单独记，不当洞）、内网 IP、隐藏路由
3. 每个端点 1 次最小请求定性：需登录？需签名？参数结构？
4. 参数矩阵：每端点列 参数/类型/示例值/可否枚举 ID
- 产出：endpoint map（端点 × 前置条件 × 参数），进 journal

## 阶段 4 — 洞型测试（严格按 严重→低 顺序，出实锤即停该型）
每型固定三要素：探测法 → 实锤标准 → 判死标准。前 3 型出实锤后仍继续补中低危（报告要厚），但时间 80/20。

### 4.1 严重（先打）
| 型 | 探测 | 实锤标准 | 判死 |
|---|---|---|---|
| RCE/命令注入 | 参数带 `; sleep 1` 延时回显、`|`、`$()` | 回显命令输出或延时>1s 且对照组无 | payload 全被过滤且无回显通道 |
| SQL 拖库 | 单引号 `\'` 报 500 且随 payload 变 → 盲注 `sleep 1` | 真读出表/列内容（哪怕 1 行） | 白名单键/整型过滤，payload 不改变响应 |
| 未鉴权数据接口 | 阶段 3 端点中"无 cookie 可访问"的，换 ID/参数 | 真读到非本人/非公开数据（字节级 diff 证明全量） | 无未鉴权端点 |
| SSRF→云元数据 | URL/webhook/redirect 参数塞 169.254.169.254/127.0.0.1 | 响应含 metadata token 或内网服务回显 | 打外网参数全过滤（万华型） |
| 反序列化 | cookie/参数里塞已知 gadget 首字节（Java `aced0005`、.NET `rO0AB`） | 500 且堆栈含 deserialization 相关 + 可控 | 首字节即 403/400 |
| 文件上传 | 有上传入口则传 canary 文件（.txt/.jpg 内嵌） | 可回读自己传的、或可执行 | 入口不存在或强校验（只报不过滤扩展名的弱洞） |

### 4.2 高
| 型 | 探测 | 实锤标准 | 判死 |
|---|---|---|---|
| IDOR/BOLA | 有 ≥2 可用账号：A 的资源 ID 换 B 读（账号走 `tools/mailacct.py` 邮箱 / 手机号用户侧） | 真读到 B 数据（截图 diff） | 拿不到 2 账号（审核注册/滑块挡）→ 线判死 |
| 越权（垂直） | 普通 cookie 打 admin 端点 | 真执行管理操作 | 全 403 |
| 认证绕过 | alg:none/空 token/过期 token | 真进管理面读到数据 | 网关双校验（签名+URI）→ 判死 |
| 业务逻辑 | 改金额/数量/跳步 | 真下单/真改数据 | 服务端校验兜底 |
| race/并发 | 余额/券/库存类并发 2~5 个（不轰炸） | 余额真变/超扣 | 服务端原子锁 → 判死 |

### 4.3 中
| 型 | 探测 | 实锤标准 |
|---|---|---|
| 存储 XSS | 找写入点（昵称/留言/公告）回显到他人/管理页 | 真回显 `<script>` 原样且过不了一致性过滤 |
| 用户名枚举 | 登录/找回密码 200 vs 400 diff | 仅当可配合批量爆破时才算，单枚举压成低 |
| 信息泄露链 | .git/.svn/.bak/.swp/swagger/openapi/.map/actuator | 真读到源码/配置（.git 里 1 个文件即实锤） |

### 4.4 低（凑报告厚度用，单独不报）
开放重定向、CSP/头缺失、版本泄露、默认 404 页含框架名、cookie 无 Secure/HttpOnly —— 全部记 journal，写进报告"附"栏，不单开洞。

## 阶段 5 — 实锤复核（报之前过 7 问 + FP-elimination）
### 5a. false-positive-elimination（攻击性排误报，先做）
1. 追全路径：入口参数→sink，标出每个 校验/编码/过滤/WAF 点
2. 每个防御点都要过掉才算；任一处挡住 → 降"被缓解"
3. 对照组硬要求：合法值 vs payload 响应必须 diff 出差异，无差异=误报
4. 区分"设计如此"：CDN 缓存掩盖、公开素材、/plugins 返 401 = 不是洞
5. 激进重估：假设它是误报，自证不了就砍或降级
### 5b. 7 问（任一不过 → 降级或砍）
1. 影响是否可复现（同一 payload 两次同结果）？
2. 是真影响不是报错（数据真变/真泄露）？
3. 归属链三张截图材料是否齐（官网 logo+备案+跳转过程）？
4. 是否在授权范围内（逐字对 scope）？
5. 是否踩红线（限额/禁项/PII 打码）？
6. 严重性是否过定级标准（按最远可达点，不夸大、不前后不一）？
7. 对照组做了吗（同参合法值 vs payload 的响应 diff）？

## 阶段 6 — 报告产出（用户格式：可复制纯文本 + 结构化 finding）
- **工作区**：`reports/<slug>/{SUMMARY.md, metadata.json, findings/, pocs/, evidence/recon_notes.md}`
  - `findings/` 只放**已确认**洞（snake_case，无方括号）；INFO/缺头/版本泄露/阴性测试全归 `evidence/recon_notes.md`
  - 每个 finding 配 `pocs/poc_<name>.py`（骨架见 templates/finding-poc.md）
  - 出完人工整理 SUMMARY.md/metadata.json（自研，无第三方聚合依赖）
- 每洞三块，直接框起来可复制：简要描述 / 详细细节（含归属链、影响场景写具体不写空话）/ PoC（payload 克制：sleep 1、回显、读 1 行表）
- + 截图清单逐张命名（用户拍）
- + 平台适配：补天公益=积分；漏洞盒子企业=现金，报告加 CVSS 向量
- + 归档：journal\<目标>\report.md + 提交记录 submitted.md

## 目标级判死条件（全证据制，写进 journal 后不再磕）
- 未鉴权面：全 404/403 + 无弱口令入口 + 无 .git/.bak 可读 → 判死
- 认证型：拿不到 2 可用登录态（审核制/滑块/极验）→ 先走 `tools/mailacct.py` 邮箱双号 + 手机号（用户侧），仍拿不到 → 越权线判死
- WAF 型：自研 WAF 全拦 → 按 `references/waf-bypass.md` 先试"CDN 源站直连 + 业务逻辑面（WAF 盲区）"；均拦 + 源站同源 → 判死（记录 WAF 指纹备用）
- 单 www + 强 WAF + 子域全 404 → 全目标判死（lzdxdyyy 型）
